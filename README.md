# AELOS R3 控制台

用于在 Windows 上连接 AELOS 3 号机器人、预览胸部相机、执行自动任务和部署树莓派程序。仓库的 `pi_deploy_bundle/` 是当前发布的树莓派部署包。

## 下载和打开

1. 从 [GitHub Releases](https://github.com/aleistercrowleybeast666/aelos_robot/releases/latest) 下载 `AelosR3Control-windows-x64.zip`。
2. 解压整个压缩包，双击 `AelosR3Control.exe`。同一目录的 `robot.exe` 提供命令行，两个程序共用 `_internal` 目录。
3. 在「SSH配置与程序部署」填写树莓派的 SSH 地址、端口、用户名和密码。默认地址为 `192.168.1.100`，端口 `22`，用户名 `lemon`。保存的密码由当前 Windows 用户加密。

首次连接时，用系统 OpenSSH 对照实际树莓派的主机指纹建立本机记录。例如在终端运行 `ssh lemon@192.168.1.100`，核对指纹后接受，再返回控制台连接。

## 部署树莓派程序

进入「SSH配置与程序部署」并选择部署来源。两种方式都会核对 `manifest.json` 及清单中的文件 SHA-256，再通过 SSH 上传。部署会在树莓派上保留上一版备份，默认替换 `/home/lemon/aelos_auto_r3_python`。需要回退时使用同一页的「恢复备份」。

| 来源 | 用法 |
| --- | --- |
| 远程部署（默认） | 点击「部署程序」时下载仓库的当前部署包。默认地址为 `https://raw.githubusercontent.com/aleistercrowleybeast666/aelos_robot/main/pi_deploy_bundle`。可改为任意提供同一目录结构的 HTTPS 地址。 |
| 本地部署 | 选择含 `manifest.json`、`app/` 和 `owner/` 的目录。可提前保存仓库中的 `pi_deploy_bundle/`，用于现场离线部署。 |

远程地址可填部署包目录、`manifest.json` 的 HTTPS 下载地址，或对应的 GitHub 目录链接。使用默认地址时，控制台一次下载 GitHub 的 `main` 归档，再从中读取和校验部署包。Windows 控制台负责下载，树莓派只需可从本机通过 SSH 访问。

普通树莓派部署沿用机上现有 MCU 登记。已经更新 MCU 并拿到读回回执时，可在部署时登记回执。

连接时如果提示 `warm_client.py` 缺失或为 0 字节，在「SSH配置与程序部署」点击「部署程序」。上位机会核对机器人身份和空闲状态，写入并校验部署文件，最后通过刚安装的客户端读取 R3 状态。收到同一控制会话的回执后，界面才显示部署成功。

如旧版 R3 镜像的控制节点一直等待串口，ROS 重载时可能出现 SSH 在线但控制服务套接字消失。对已识别的旧版串口程序，控制台会先备份并安装退出修复，再提示重启树莓派一次。看到该提示后，重连并再次部署。已修复的机器可正常热部署。

将 [R3 MCU 动作覆盖包](https://github.com/aleistercrowleybeast666/aelos_robot/releases/download/v1.0.12/AelosR3-MCU-stand-reuse.zip) 解压，在 3 号机 U 盘模式下将包内的 `lua` 和 `dat` 合并到对应目录，再重启并部署树莓派程序。命令 1、2 首趟抓取后都后退 8 步，再校正航向并侧跨。单抱和双抱的髋部后倾补偿从 10 调为 8 个舵机指令单位，侧跨时从 5 调为 4。双抱连续退八步时减缓起步和收步，持物微转的左右差动幅度也略有缩小。此版持物小跨沿用大跨的移重、迈脚和跟脚顺序，缩短开脚幅度。新增空载连续前进 4 步；树莓派只在 MCU 回报支持时使用，旧板按两步一组执行。安装 v1.0.7 MCU 的机器可只更新树莓派，使用 6＋2 步。命令 2 回程会查询空载连续侧跨能力，控制台显示实际动作和复测结果。

命令 0 的快速起步需要 v1.0.12 的 MCU 覆盖包和本版树莓派程序。MCU 会跟踪最近已完成的空载归位或放物动作。仍有有效站姿记录时可省去重复归位。刚上电、接管或记录失效时执行归位。仅更新树莓派也可使用并行预检和失码恢复。命令 1、2 从取物开始。

## 控制机器人

在「控制 → 自动任务」选择 −90°、−45°、0°、+45° 或 +90°，也可手填范围内的任意整数。负数向左，正数向右，默认 0° 直接放物。进入大本营后，机器人按每次约 30° 的大转就近取整，随即放物。例如 +45° 执行两次右大转，+90° 执行三次，小于 15° 的绝对值直接放物。命令 2 第二趟向相反方向放，回程按已完成的大转估算掉头余量，再扫 Tag 5 对正。请配套更新树莓派部署包。

可以在给机器人上电时点击「连接机器人」。控制台最多等待约 90 秒，分别显示等待 SSH 和等待 R3 控制服务的阶段，随时可以取消等待。控制服务一旦应答即可连接。日志显示从点击到应答的耗时，配套树莓派程序还会尽可能给出本次开机后 SSH 服务最近激活和当前控制节点开始监听的时刻。部署重载控制节点也会更新后一个时刻。连接后会自动打开胸部相机预览，也可手动开关。

树莓派控制服务在收到本次 MCU 握手并核对登记后，后台查询已安装运行程序提供的动作能力。正常放物后可复用同一有效会话的查询结果。任务先于后台检查启动时，沿用已经查到的能力，补查当前任务需要的部分。每次任务仍读取当时的相机和磁力计状态。实物舵机、抓取姿势和步幅要由现场动作验证。

控制台显示任务状态、回执和最近的扫码或纠偏诊断。停止按钮经独立连接取消后续动作。收到任务结果后，运行日志会显示本机 JSON 报告的实际保存路径。

比赛部署包在 `app/config/route_steps.json` 中启用了 `continue_estimated_route`。命令 0、1、2 会在当前路段尝试找码和纠偏。仍缺少可靠位姿时，沿该段剩余动作前进，到下一动作边界再看码。报告分别记录实际确认的码和估算进度。命令 1、2 在规定取物点确认只有一块时单抓，数量无法判断时默认双抱，实际件数和落点需现场确认。各码对应的动作、限制和日志示例见[去程与回程的失码找回说明](docs/checkpoint-search.md)。

命令 1、2 首趟取物沿用抓取前的路线朝向。连续后退 8 步后、开始左跨前必须检查航向。首趟中转区左跨的名义步数为 11 大跨加 1 小跨，按航向分组执行。有当前站位的可信 Tag 1 时采用视觉。仅有磁航向且偏差较小时，静止复测确认同向，并在预计小转能改善时发出一次纠偏，记录转后余差。两个传感器都缺少有效航向时，下一组最多左跨两步再查。控制台会列出连续后退结束和每组左跨结束时的偏航、实际转向动作、转后余差。读数暂时不可用时，日志单独标明航向未确认。

去程 Tag 3 → 4 默认右大跨 4 步。可信横偏会合入这组右跨。侧跨结束时，如果新读到的 Tag 3 和磁航向都在直行容差内，程序保留视觉余差并直接前进。途中读到可信的 Tag 3 可以校正航向。最终漏扫时，当前站位的 Tag 2 可提供方向参考。命令 0、1、2 的去程共用这段直行。计划的大右跨全部收到回执后，如果同一站位的新鲜 Tag 3 多帧确认航向、横向位置，并且按场地图估计有足够的前向余量，优先连续前进 8 步。按实测补成五个大右跨（3＋2）同样适用。到动作边界重新看码、查航向，条件允许时再连续前进 4 步。位姿不稳、前方余量不足或偏航时缩短步组。在第 2 或第 4 步结束后，若静止时的新鲜相机窗口只见 Tag 3、磁航向稳定且之前没有 Tag 4 距离线索，则复用该窗口决定下一组。远处 Tag 4 主要用于估计距离。`tag4_forward_trial.heading_use_within_m` 默认为 `0.35` 米，可按场地实测调整。

起步找 Tag 1 时，若相机正常而整窗未见任何码，命令 0 默认前进两步再扫，命令 1、2 首趟默认后退两步再扫一次。已有可信距离时按实际远近调整。命令 2 再次从接驳点出发时使用该处原有找码策略。

去程 Tag 1→2 的名义直行是 10 步。Tag 1 的实测前后误差合入直行计划；途中看到 Tag 2 后，按新距离决定还要走几步。只有部分帧显示码已贴近时，先缩短余程并复查，再决定是否开始侧跨。

命令 0、1、2 的去程共用 Tag 2 进近设置。`tag2_forward_trial.target_distance_m` 默认为 0.18 米，容差为 0.035 米。距离按地面到 Tag 2 的位姿计算。每次选择补进步数时，预计落点的最近端须达到 `minimum_strafe_distance_m`（默认 0.145 米）。双抱补进后若新测距已在目标范围内，就用当前航向准备右跨。

持物时图像 y 会随胸部俯仰改变。日志保留原始像素，并在有地面码光学位姿时给出相机俯角和沿地面到码的距离。旧站姿的 344 像素只作为历史记录，路线仍按当次地面码位姿补偿。

胸部广角画面的查看方式和 Tag 3 边缘纠偏条件见[胸部相机与扫码航向](docs/chest-optics.md)。

如果任务中相机短时断流，程序按当前路段重新取帧。人工停止或控制连接中断后，已经下发且完成状态未知的动作保留在报告里。重新连接时，同一次抓取或行走请求只会分派一次。若控制台提示上一趟可能持物，取下方块、摆稳机器人后点击「恢复空载站姿」。

### 命令 2 的两趟搬运

首趟放物起立后，机器人按以下名义步数空载返回。空载掉头中途磁场强度异常时，先原地复测。磁场仍异常时，丢弃这次磁航向；若当前站位的多帧目标码已确认方向适合微调，直接转入正式扫码。否则继续剩余的预设转向。左右均以当时的机身朝向为准。

| 区段 | 名义动作 |
| --- | --- |
| 大本营 → Tag 6 | 掉头 180°，扫 Tag 5 纠偏，前进 8 步，扫 Tag 6 |
| Tag 6 → Tag 7 | 左跨 7 步，核对返程航向，前进名义 8 步。在姿态稳定且 MCU 支持时，侧跨用 3＋2＋2，直行用 4＋4 |
| Tag 7 → 中转区 | 右跨名义 9 步，扫 Tag 1，分别调整前后和横向位置。向中转区前进名义 12 步，掉头 180°，再扫 Tag 1。找码借用的前进步数计入这 12 步 |
| 接驳取物 → 第二趟去程 | 掉头后先检查退距，机身正前方到码不足 18 cm 时先后退两步再检查。随后朝取物点右跨名义 4 步，再前进最多 4 步。抵达示教位置或近处已出现方块时切换到视觉取物。抱稳后按实际走过的动作后退、左跨，重扫 Tag 1，沿去程通道送入大本营，放下后结束 |

接驳站采用 11 月 27 日 00:23 的空载胸部相机记录。机器人面向方块时，Tag 1 位于画面左侧。三帧 `/map` 原始位置的中位数约为 `(0.1914, 0.4495, -0.1374)` 米。该参照只用于中转区接驳。方块的位置和数量由色块识别单独判断。

回程 Tag 5、6、7、1 的目标航向相对各自码面依次为 180°、0°、0°、180°。中转区掉头后，再用新帧按 0° 校准 Tag 1。回程时，程序用同一码的多帧视觉航向更新磁航向参考。扣除帧间波动后，余差超过配置容差（默认 8°）且 MCU 已确认支持空载小转时，会先小转再扫码。超过 25.5° 时可选空载大转。回程中相机正常、漏码且有可能走过头时，程序先后退两步重扫。若新帧仍指向同一码且距离过近，可再退两步。读到远码或其他码时按该路段的观测和行进方向处理。

树莓派程序的 `checkpoint_scan.py` 提供共用的读帧和检查点扫码入口。`checkpoint_alignment.py` 负责视觉转向和磁航向参考，`checkpoint_errors.py` 区分相机故障、控制连接异常和漏码。各路段仍在自己的路线文件中决定是否借步、侧跨或继续行进。

返程反扫 Tag 5 时分别检查朝向和横向位置。报告中横偏为负表示机身在目标左侧，应向自己的右侧跨。横偏明显时先跨一步，用新帧测出改善后可连续跨两至三步。掉头后如果连续两个健康观察窗里一个码都没有，先空载后退两步再扫。只有新读数仍显示过近，才追加后退。门口横向容差默认 5.5 cm。返程侧跨前，Tag 6 的机身前向距码范围为 15–24 cm，Tag 7 为 12–21 cm。返程 Tag 1 另检查横偏。前后调整后，若新帧的距离分散在 1 cm 内、整组落在允许区间边缘 5 mm 内且航向合格，就继续返程。若连续两次前后调整跨过目标区间，程序可根据两端的稳定实测距离选择误差在 1 cm 内的落脚点，下一段先侧跨一步核对航向。各距离区间可在 `command2_empty_departure` 调整。

找 Tag 7 时，如果胸部相机连续只读到邻道的 Tag 3，先后退两步，再用最近一次可靠返程码校准过的磁航向对准路线 180°。航向对正后每前进两步找一次 Tag 7，最多两组。看到 Tag 7 即使用它的当前位姿纠偏。该恢复动作单独计数，后面的 9 步右跨按原计划执行。

可在部署包的 `app/config/route_steps.json` 查看和调整路线。MCU 回执记录完成的动作，实际落点会随负载和地面变化。

## 查找和分享任务报告

| 运行日志按钮 | 用法 |
| --- | --- |
| 打开日志文件夹 | 在资源管理器中查看或清理报告。默认目录为 `%LOCALAPPDATA%\AelosR3Deploy\task_reports`。 |
| 更改日志目录 | 选择新文件夹后，下次收到的报告就保存在那里。以前的文件仍在原目录。所选目录暂时无法写入时，当次报告会保存到默认目录，下次继续尝试所选目录。 |
| 分享任务报告… | 默认方式为 GitHub。可以启用后续报告自动推送，也可以手选最近一份或多份 JSON 单次分享，包括旧目录中的报告。 |

### 推送到 GitHub

1. 在分享窗口填写日志仓库的 `owner/repo` 或 GitHub 仓库网址。默认是 `aleistercrowleybeast666/aelos_robot`。公开仓库中的日志分支也公开。如仅供队内查看，可新建私有仓库，创建时勾选添加 README，再把这里改为它的仓库名。
2. 用具有目标仓库写权限的账号创建短期个人访问令牌。仓库所有者或具备写权限的组织成员可使用细粒度令牌，选中目标仓库，授予 **Repository permissions → Contents → Read and write**。在分享窗口输入令牌，或在启动控制台前设置环境变量 `AELOS_GITHUB_TOKEN`。[GitHub 令牌设置说明](https://docs.github.com/zh/authentication/keeping-your-account-and-data-secure/managing-your-personal-access-tokens)
3. **自动推送**。将完整的 GitHub 访问令牌粘贴到令牌框，即会启用。手动逐字输入时按回车，或点击「启用自动推送」。控制台用当前 Windows 用户的 DPAPI 加密保存令牌，每次收到自动任务、手动扫码、停止、部署检查、部署或回滚的终结回执，就先写本机报告，再从后台发送。定时状态轮询及相机预览不生成报告。本次打开控制台以来若已有报告，启用时也会发送最近一份。网络中断后会在后台重试。关闭自动推送会清除控制台保存的令牌，赛后也可到 GitHub 撤销授权。
4. **单次推送**。要补传以前的报告，可以手选文件并点击「推送到 GitHub」。控制台将本批新增报告作为一次提交写入独立的 `robot-logs` 分支，队员在该分支的 `reports/年/月/日/` 下查看。相同报告会跳过。两人同时推送时，控制台会基于最新提交重试。若仍提示冲突，可以稍后重传同一批。

GitHub 对外部协作者使用细粒度令牌写入他人仓库有限制。遇到这种情况，可让队员通过下面的共享目录交报告，由仓库所有者或具备权限的组织成员统一推送。[GitHub 对协作者的令牌限制](https://docs.github.com/en/authentication/keeping-your-account-and-data-secure/managing-your-personal-access-tokens#fine-grained-personal-access-tokens-limitations)

### 导出 ZIP 或写入共享文件夹

在分享窗口切换方式即可。**ZIP** 适合把一场试跑的报告打包带走。**共享文件夹** 支持有写入权限的 Windows 共享路径（如 `\\比赛电脑\机器人日志`），也支持同步盘客户端已设置同步的本地文件夹。共享目录写入中断后可重选同一批报告再发，已写入且内容相同的文件会跳过。

三种方式都从所选任务报告生成分享副本，保留命令、时间、结果和诊断，移除报告顶层的 SSH 目标以及可识别的凭据字段和令牌文本。本机原件保留在保存目录。场地、动作和故障细节仍可供队员排查，选择公开仓库时也会向读者公开。

## 命令行

在解压目录执行；PowerShell 下使用 `./robot.exe`。源码目录也可运行 `python -m r3_deployer`。

```powershell
./robot.exe config --ask-password
./robot.exe check
./robot.exe update
./robot.exe update --source local --local-path 'D:\Robot\pi_deploy_bundle'
./robot.exe config --source remote --remote-url 'https://example.org/r3/pi_deploy_bundle'
./robot.exe status
./robot.exe run 0
./robot.exe run 2 --drop-yaw-deg 45
./robot.exe stop
```

`config` 保存设置，`update` 的 `--source`、`--remote-url` 和 `--local-path` 仅覆盖本次部署。`update --run 0` 可在部署完成且控制服务通过检查后启动命令 0。

## 从源码运行和打包

在 Windows x64 上使用 Python 3.14 构建。

```powershell
python -m pip install -r requirements.txt
python -m r3_deployer
python -m pip install pyinstaller==6.16.0
python tools/build_windows.py
```

构建包含 U 盘核验文件的便携版时，给打包脚本传入 `--mcu-overlay 目录`。该目录应含 MCU 覆盖包中的 `MANIFEST.json`、`dat` 和 `lua`。

打包生成 `dist/AelosR3Control-windows-x64.zip` 和 SHA-256 校验文件。可通过 `Get-FileHash .\AelosR3Control-windows-x64.zip -Algorithm SHA256` 核对。更新树莓派程序时，将新包整体替换仓库中的 `pi_deploy_bundle/`，随包提交 `manifest.json`。已安装的控制台在下一次远程部署时从 `main` 获取更新。
